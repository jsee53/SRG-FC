# SRG-FC

새릉골 풋살 동호회(SAE REUNG GOL FC) 멤버 실력 랭킹 & 팀 짜기 사이트. React + Vite로 만든 정적 사이트로, 서버 없이 GitHub Pages에서 호스팅됩니다.

🔗 **https://jsee53.github.io/SRG-FC/**

## 로컬에서 실행하기

```bash
npm install
cp .env.example .env   # Supabase URL/anon key 채우기
npm run dev
```

`http://localhost:5173` 에서 확인할 수 있습니다.

## Supabase 설정 (최초 1회)

멤버 데이터는 이제 Supabase(Postgres) DB에서 관리됩니다.

1. https://supabase.com 에서 새 프로젝트 생성
2. 대시보드 **SQL Editor**에서 `supabase/schema.sql` 내용을 그대로 실행 (테이블 생성 + RLS 정책 + 기존 26명 데이터 이전 + 게시판 + 일정)
3. `Settings > API`에서 `Project URL`, `anon public key`를 `.env`에 채우기 (`.env.example` 참고)
4. `Authentication > Users`에서 관리자 계정을 이메일/비밀번호로 직접 추가 후, `schema.sql` 맨 아래 안내대로 `admin_users` 테이블에 그 유저를 등록
5. GitHub Actions로 배포하려면 저장소 **Settings > Secrets and variables > Actions**에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`를 등록 (Vercel이면 프로젝트 Environment Variables에 동일하게 등록)

## 로그인 / 회원가입

헤더의 "로그인" 버튼에서 이메일/비밀번호로 자유 가입할 수 있습니다(관리자 승인 불필요). 가입 시 기존 로스터에서 자기 이름을 선택하면 계정과 멤버가 연결되고, 연결된 멤버는 헤더 버튼을 눌러 "내 정보"에서 등번호/출생년도/포지션을 직접 수정할 수 있습니다(이름/티어/능력치/한줄평은 관리자만 수정 가능 — 본인이 이름을 바꾸면 다른 멤버로 오인될 수 있어 막아뒀습니다). 로그인 없이 둘러보는 건 그대로 열려있습니다.

관리자는 멤버 상세보기의 "수정" 버튼으로 모든 필드를 편집하거나 멤버를 완전히 삭제할 수 있고, 랭킹 탭 상단의 "멤버 추가" 버튼으로 새 멤버를 등록할 수 있습니다. 관리자에게 "능력치 권한"을 받은 계정은 상세보기에서 "능력치 수정" 버튼으로 등급/능력치만 고칠 수 있습니다(이름/포지션 등 다른 필드는 손댈 수 없음).

전체 순위는 종합 점수(OVR) 높은 순, "이름순" 보기에서는 가나다순으로 정렬됩니다 (`src/utils/tier.js`). 내부 데이터는 S~D 다섯 등급 그대로지만, 알파벳 등급이 위계감/박탈감을 준다는 의견이 있어 화면에는 게임 카드 등급 느낌으로 **IMMORTAL(S) > ETERNAL(A) > TRANSCENDENT(B) > LIMITED(C) > LEGEND(D)** 로 표시됩니다. OVR은 6개 스탯의 단순 평균(포지션 가중치 없음)으로 계산되어 카드/상세보기와 팀 짜기 밸런싱에도 쓰입니다 (`src/utils/calcOvr.js`).

## 관리자 도구

로그인 상태에서 헤더 버튼 → "내 정보"를 열면 관리자 계정에는 "관리자 도구" 버튼이 보입니다. 여기서 가입된 계정 목록(이메일 + 연결된 멤버 이름)을 볼 수 있고, 계정-멤버 연결을 끊거나, 특정 계정에 "경기 일정 등록" / "공지사항 작성" / "등급·능력치 수정" 권한을 각각 주고 뺄 수 있습니다.

## 게시판

"게시판" 탭에서 누구나 글/댓글을 읽을 수 있고, 로그인한 계정만 글쓰기/댓글 작성이 가능합니다. 글/댓글은 작성자 본인만 수정할 수 있고, 삭제는 작성자 본인 또는 관리자가 할 수 있습니다. 글/댓글에 좋아요(♡)도 누를 수 있습니다.

관리자, 또는 관리자에게 "공지사항 작성" 권한을 받은 계정은 글쓰기 시 "공지사항으로 등록"을 체크할 수 있습니다. 공지 글은 작성일과 무관하게 항상 목록 맨 위에 고정되고, 눈에 띄는 테두리/배지로 강조됩니다.

## 경기 일정

"일정" 탭에서 누구나 등록된 일정(날짜/시간/참석자)을 볼 수 있고, 관리자이거나 관리자에게 일정 등록 권한을 받은 계정만 새 일정을 등록/수정/삭제할 수 있습니다. 시간은 30분 단위로 시작~종료를 선택해 "19:00 ~ 22:00"처럼 표시됩니다. 참석자는 로스터 멤버를 선택하거나 용병을 이름+티어로 자유롭게 추가할 수 있습니다.

일정 등록 후 그 참석자 그대로 "팀 짜기" 버튼으로 바로 팀을 나누고 결과를 그 일정에 저장할 수 있습니다(용병은 등록해둔 티어로, 로스터 멤버는 실제 능력치로 밸런싱). 저장된 팀 구성은 일정 카드에 그대로 표시되고, 언제든 "팀 다시 짜기"로 재구성할 수 있습니다.

일정을 등록/팀을 짠 것만으로는 아무 통계도 안 남고, **관리자가 그 일정을 "경기 성사됨"으로 표시해야** 두 가지가 활성화됩니다: (1) 참석자 중 로스터 멤버의 참석 횟수가 올라가고(랭킹 상세보기에 표시), (2) 저장된 팀별로 "같은 팀 멤버끼리만" POM(Player of the Match) 투표를 할 수 있게 됩니다 — 투표는 팀당 1인 1표로, 각 팀에서 최다 득표자(동률이면 전원)가 그 경기의 POM으로 집계되어 랭킹 상세보기에 "받은 횟수"로 표시됩니다. "팀 초기화" 버튼으로 팀 구성만 지울 수도 있습니다(이 경우 그 경기의 POM 투표도 같이 삭제됩니다). 지난 일정의 참석자 명단도 관리자/일정 권한 계정이 언제든 수정할 수 있습니다(단, 참석자를 수정하면 그 일정에 저장된 팀 구성과 투표는 초기화됩니다).

## 팀 짜기

"팀 짜기" 탭에서 참석자를 클릭으로 담고, 로스터에 없는 용병은 인원수+티어만 선택해 추가할 수 있습니다. 팀 수(2/3)를 고르면 총 참석 인원을 능력치 기준으로 최대한 균등하게 자동 배분합니다. 결과가 마음에 안 들면 "다시 나누기"로 재계산할 수 있습니다.

## 배포

`main`, `jsee53` 브랜치에 push하면 GitHub Actions가 자동으로 빌드하고 GitHub Pages에 배포합니다 (`.github/workflows/deploy.yml`). 저장소 Settings > Pages에서 Source가 "GitHub Actions"로 설정되어 있어야 합니다.
